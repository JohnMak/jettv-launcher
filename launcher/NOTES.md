# ATV Launcher notes

Package `com.alexmak.atvlauncher`, Java, minSdk 30 (projector: Android 11; TVs: Android 14), targetSdk 34. Single code path, no SDK_INT forks: Wi-Fi SSID/RSSI via WifiManager.getConnectionInfo, system-broadcast receivers registered without export flag, no Pattern.UNICODE_CHARACTER_CLASS (Android 11 rejects flag 256).

## Build / install
- `tools/build-and-install.sh` builds only. `install` also installs via the relay (push + `pm install -r`), grants ACCESS_FINE_LOCATION (SSID) and READ_TV_LISTINGS (content feed) and allows the GET_USAGE_STATS app-op (usage ranking). `home` additionally runs `cmd package set-home-activity`.
- Toolchain lives in `.toolchain/` (JDK 17 from brew `openjdk@17`, SDK, Gradle home).

## Configuration: `app/src/main/res/values/config.xml`
- Favorites: `favorites_seed` is only the first-run seed (persisted afterwards in SharedPreferences `favorites`; uninstalled apps are dropped).
- Wallpaper: put an image in `app/src/main/res/drawable/` (e.g. `wallpaper.jpg`) and set `wallpaper_drawable_name` to `wallpaper`. Empty = pitch black. Rebuild required.
- Greeting/date language: `date_language` (`ru` / `en`); texts in `greetings_ru`, `greetings_en`.
- VPN top-bar item: shown/hidden (`vpnButtonVisible`) and the VPN app (`vpnPackage`) are chosen in the launcher settings. VPN apps = packages with a service guarded by BIND_VPN_SERVICE found via `queryIntentServices(android.net.VpnService)` (`VpnAppsLoader`, manifest `<queries>` entry; pure rules in `VpnApps`: filter, `choose` = stored > `vpn_default_package` (app.hiddify.com) > first installed > none = item hidden, `cycle`). OK (`VpnApps.decide`): VPN on AND the package has a toggle-off component in the parallel config arrays `vpn_toggle_off_packages` / `vpn_toggle_off_components` (now Hiddify's ShortcutActivity) -> start it and wait up to 15 s for the network callback; otherwise (off, or no component) -> leanback/launcher intent of the package (`openVpnApp()`). The status dot is always the system VPN state. MainActivity re-reads the settings in onStart.
- Key interceptor (accessibility service, off until enabled in system settings): `KEY_REMAP_SERVICE`, `HOME_KEY_SERVICE`, `settings_key_keycodes`, `app_key_keycodes` + `app_key_packages` (parallel arrays).

## Home screen
- Top bar (clock/date left; right: VPN text + dot, Wi-Fi/ethernet icon + label, launcher-settings sliders icon (`ic_sliders_horizontal`, opens `LauncherSettingsActivity`), plain gear - no backgrounds, right edge on the 56dp margin, `TopBarItem`) -> favorites row -> «Продолжить просмотр» -> «Рекомендации». Down/Up moves between rows, empty rows are skipped, every row remembers its column.
- Favorites: any number of apps in a horizontal row spanning the content width (56dp margins, same as clock/top bar/feed rows/info fields). No box behind it. Tiles are 16:9 and auto-sized by `FavoritesRowLayout`: n = favorites + apps button, width = clamp((content - (n-1)*16dp)/n, 96dp, 220dp); tiles are spread edge to edge with equal gaps (first flush left, last flush right); if they do not fit at 96dp the row scrolls with a 16dp gap. Recomputed on layout and on every favorites change. The row CONTINUES after the apps button with the non-favorite launchable apps sorted by launch count (`UsageRanking`, same metric as AllApps; `app_header_packages` and our own package excluded; re-sorted when the launch counts change), same tile size and gap, extending off-screen right (`FavoritesRowState`: kinds FAVORITE / APPS_BUTTON / FREQUENT; `FavoritesRowLayout.compute(content, fitCount, total, ...)`: only favorites + button are fitted edge to edge). Focus RIGHT scrolls the row (animated 250 ms, `FavoritesRowLayout.scrollFor`: minimal move that keeps the focused tile fully inside the 56dp margins; at index <= the apps button the scroll is 0 while the favorites fit); HOME / onStart (`resetFavoritesRow`) scroll to 0 and cap the remembered favorites column at the apps button. The glass follows the scrolled tile. Long-press on a continuation tile: «Добавить в главные» / «Управление приложением»; opened dots apply too. No scaling and no name label on focus: only the glass highlight (drawn outside the row, not clipped). Last tile is the apps button (opens AllAppsActivity). Long-press OK on a favorite: menu «Переместить» (Left/Right moves, OK/Back finishes) / «Убрать из главных». Changes persist immediately.
- Page background (home and AllApps) is the focused thing's picture, blurred and dimmed: for an app tile its leanback banner, else the launcher icon at xxxhdpi (`AppBackdropImage`); for a feed card its poster. One pipeline: `BackdropController` (debounce `BackdropPlanner` 150 ms, `BackdropBlur` to 160x90 on the worker (progressive bilinear halving, 3 box passes radius 14 = sigma ~14 px, no dim in the bitmap, `BackdropVignette` overlay: black alpha from 75% in the centre to 40% at the edges (brightness 25% -> 60%), drawn dithered by `BackdropImageView` as an elliptical radial gradient; 128 cached = 7.4 MB; shown with bitmap filtering), LRU cache of the blurred results, 600 ms ease-in-out (AccelerateDecelerate) crossfade/fade `PosterBackdrop`), keyed by `BackdropKeys` (poster URI or `app:<package>`). The top bar keeps the last backdrop; the apps button and a card without poster fade it out. There is no big title, no colour tint.
- AllAppsActivity: header row at the top right with icon buttons for `app_header_packages` (config.xml: RuStore, Google Play, Uptodown, Settings; only installed ones; excluded from the grid; Up from the first grid row enters it, Left/Right inside, Down back; OK launches). 5-column grid in sections (`app_group_*` in config.xml: Онлайн-кинотеатры, Плееры и инструменты, Другое; empty ones hidden), ordered by launch count (below) inside a section. It opens instantly from `AppCache` and refreshes in the background (DiffUtil); long-press OK -> «Добавить в главные» / «Убрать из главных»; Back returns home.
- Launch count (`LaunchStats`, one metric used by the all-apps order and the recommendations): transitions of the foreground package into an app, from `UsageStatsManager.queryEvents` (ACTIVITY_RESUMED) over the last 30 days. Needs the app-op: `appops set com.alexmak.atvlauncher GET_USAGE_STATS allow` (install script does it); without it every app counts 0 and lists are alphabetical.
- Feed (`FeedLoader`, needs `pm grant ... READ_TV_LISTINGS`): reads TvProvider preview_program and watch_next_program of all apps (no selection allowed; only needed columns). Rows of non-launchable packages are skipped, bad rows are logged and skipped. A ContentObserver (Preview/WatchNext/Channels URIs, registered in onStart, removed in onStop, debounced 1 s) reloads; no polling.
  - «Продолжить просмотр»: watch-next, strictly by LAST_ENGAGEMENT_TIME desc (no time = last), max 20.
  - «Рекомендации»: 30 slots. Every publishing app gets 1 card (highest WEIGHT, else first channel order); the rest is split by launch counts (largest remainder; never-opened apps keep exactly 1; capped by what the app publishes). More apps than slots: top apps by launches, ties by package name. Order = apps interleaved evenly by their share. Logic and tests: `FeedBuilder`.
  - Both rows are image-only cards. Each row has its own info field right under it (`FeedInfoField`, one layout `view_feed_info` used twice): a horizontal row of separate views with 20dp gaps (centred vertically): title (Outfit ExtraBold 800, max 700dp, ellipsized), «Сезон 2, серия 5» (Outfit Thin; TvContract SEASON/EPISODE_DISPLAY_NUMBER; omitted for movies; `FeedInfoLine.season`), rating icon + number (Thin), then «КП 7.9» and «IMDb 8.1» (13sp dim label + Thin number, only when Kinopoisk has them; see Kinopoisk below). Below that line a Kinopoisk description (14sp Thin, dim, max 3 lines, width 760dp, ellipsized): Kinopoisk `shortDescription`, else the first 3 sentences of `description` (`KinopoiskInfo.describe`); never the provider's description. The source app is NOT in the line: it is the badge on the card (below). Rating (`Rating`): one 10-point scale with one decimal, from TvContract REVIEW_RATING: stars x2, percentage /10, thumbs "up,down" counts -> up share x10; absent/garbage = omitted; > 8.0 is "top". Icon is an ImageView: `ic_star` normally, `ic_laurel` for top (placeholder shapes; Phase 2 swaps content). The field always keeps its fixed height (90dp + 4dp top margin = `FeedPageShift.INFO_DP` 94: line 30dp, description 56dp; page height 1030dp, feed block top 460dp; 8dp above the «Рекомендации» heading). Page shift (`FeedPageShift`, pure, tested; screen 540dp at UI scale 100 %): focus in «Продолжить просмотр» = 430dp (heading at 30dp, the second row's cards visible under its info field); focus in «Рекомендации» = 488dp when the first row exists (that row's info bottom stays 12dp above the screen bottom; first row's cards remain visible at the top, its heading scrolls out), else 430dp and is only faded (alpha, 180 ms): visible while focus is in its row, so nothing shifts. The favorites move hint is a separate line above the favorites row (`move_hint`), also alpha only.
  - Card badge (`card_badge`, FeedAdapter): the source app's launcher icon, 22dp square at alpha 0.7, flush with the poster's bottom-left corner; clipped by `Tiles.roundCorners` (top-right 6dp, bottom-left = the poster's 12dp, others square). It scales/dims with the poster as one card (`Tiles.setCardSelected`, pivot = poster centre).
  - Backdrop: while a feed card is focused the page background is its poster, centre-cropped to 16:9, downscaled to 160x90, box-blurred and dimmed to 38% (`BackdropBlur`, worker thread, from the cached bitmap, no fetch), crossfaded 600 ms ease-in-out (`PosterBackdrop`). Debounced 150 ms (`BackdropPlanner`); poster not decoded yet = keep current look.
  - Posters: `PosterCache` (8 MB LRU, downsampled decode, disk cache `cacheDir/posters` ~30 MB, 5 s timeouts, content:// via ContentResolver). Cleartext HTTP is allowed only for imagetmdb.cubnotrip.top and imagetmdb.cub.best (`res/xml/network_security_config.xml`).
  - OK on a card: `Intent.parseUri(intent_uri)`; failure is logged and a toast «Не удалось открыть» is shown.
- Weather (`WeatherController`, `WeatherItem`, `WeatherDisplay`; data layer `MetProvider` (MET Norway, the single source) + `WeatherModel`; `GeoIpClient`/`GeoLocation` carry `country_code`; `WeatherPrefs` treats a location without stored country as unset): item in the left column under the date (line 1: 22dp condition icon + 20sp temperature + phenomenon word if any, e.g. `+4° дождь`; line 2, dimmer 14sp: city, 17dp gap, `+4° / −1°` = day max / night min; Outfit). `Weather.phenomenon` comes from `WeatherModel.phenomenon(symbol_code)` (thunder > sleet «мокрый снег» > snow «снег» > *rainshowers / heavyrain «ливень» > rain «дождь» > fog «туман»); empty for clear/cloudy. Prefs keys `w3_*` (v2 ignored). Cached snapshot is shown at once; `start()` (onResume) and an hourly timer (running only between onResume and onPause) refresh by `WeatherRefreshPolicy`: no city = never; no snapshot / another city = always; activation needs the snapshot >= 10 min old, the hourly tick >= 60 min; `stop()` in onPause. It is a focus zone `WEATHER`: LEFT from the first top-bar item enters it, RIGHT goes back to the top bar, DOWN to favorites (UP from favorites still goes to the top bar). OK = refresh the weather now (no IP detection here; the city is chosen only in the settings screen); without a city OK opens the settings screen on the «Город» row. `start()` also refreshes at once when the stored city differs from the one the cached snapshot was fetched for (`w3_location` = `GeoLocation.key()`, `WeatherRefreshPolicy`); a snapshot of another city is never shown. No location yet: `ic_cloud_off` + «Определить город». Background failures are only logged and keep the old data; a failed OK press shows «Не удалось обновить погоду». Icons: `WeatherIcons` is the single WeatherIcon -> R.drawable switch.
- Idle (`IdleTimeline` pure, built from `LauncherSettings`; `IdleController` reloads the settings on every start): after the dim delay (default 30 s; 15/30/60/120 s) without input -> black overlay fades to 60 % (UI at ~40 %), after the screensaver delay (default 2 min; 1/2/3/5/10 min) -> `Screensaver` fades in (1 s): background (starfield or NASA video, below) under the shared clock/date/weather overlay. Any key while dimmed/screensaver only wakes (300 ms fade) and is consumed together with its key-up. A disabled stage (`dimEnabled` / `screensaverEnabled` false) never happens; a dim not earlier than the screensaver is overtaken by it. Started in onStart, stopped in onStop (resets to active). AllAppsActivity has no dim (separate activity; not added). System dream: `StarfieldDream` (same `Screensaver`, same selection); install script sets `screensaver_components`/`screensaver_enabled`, `tools/restore.sh` deletes `screensaver_components` and sets `screensaver_enabled=1` (original: `backup/screensaver-before.txt`).
- Opened-app dots (`RecentApps` pure, `LaunchStats.resumedSince`): packages with ACTIVITY_RESUMED after boot (wall time), launchable and not the launcher; queried on every onResume (worker). Every opened tile of the favorites row (favorite or continuation) carries a 5dp white dot (70 %) under it. There is no recent line / «Закрыть все»: a normal launcher cannot unload apps on Android 14. DOWN from any favorites tile -> «Продолжить просмотр», UP from the feed -> favorites.
- Kinopoisk ratings/description (androidtv-3km; source kinopoiskapiunofficial.tech, header X-API-KEY): token `kinopoisk.token` in untracked `launcher/local.properties` -> `BuildConfig.KINOPOISK_TOKEN` (build.gradle validates UUID format; missing/malformed = empty = feature off: no threads, no requests). `FeedLoader` also reads COLUMN_RELEASE_DATE (-> `FeedItem.year`, `parseYear`) and COLUMN_TYPE (`FeedItem.type`, -1 if null). `TitleMatch` (pure): `clean` (lower case, «(2019)», «сериал», season suffixes and punctuation removed; used as the search keyword), `normalize` (+ ё->е), `kindOf` (EPISODE if season/episode numbers or TYPE episode/season; else SERIES/MOVIE by TYPE; else UNKNOWN), `pick` (exact normalized nameRu/nameEn, type filter MOVIE = not series / SERIES+EPISODE = TV_SERIES, MINI_SERIES, TV_SHOW, year +-1 unless EPISODE or unknown, most votes wins; no match = nothing), `key` (name|year|kind; episodes use year 0). `KinopoiskModel` (URLs + parsers: search `films[]` filmId/nameRu/nameEn/type/year(string)/ratingVoteCount; film `kinopoiskId`/ratingKinopoisk/ratingImdb/shortDescription/description; ratings may be null or the string "null"). `KinopoiskClient`: 2 GETs via `HttpText` (10 s timeouts); HTTP 429 -> 60 s back-off where every lookup fails at once; errors are returned, never cached. `KinopoiskCache`: `filesDir/kinopoisk_cache.json`, hit 7 days, miss (no match or all empty) 24 h, errors never stored, max 400 entries, atomic save when the last queued lookup finishes; an unreadable file is logged and replaced by an empty cache. `KinopoiskService` (main thread API, 2 daemon worker threads): `prefetch(feed items)` after every feed apply, `info(item)` never blocks (returns what the cache has, else starts a lookup; failed key retried after 60 s), calls `onInfo(key)` on the main thread when data arrives; MainActivity re-fills the info field only if that card is the focused one (text swap inside the fixed-size field, no layout shift). Fixtures captured from the live API (no secrets): `kp_search_breaking_bad.json`, `kp_film_series.json` (404900), `kp_film_movie.json` (1209193), `kp_film_no_kp_rating.json` (1005914).
- Unit tests (JVM, no device): `cd launcher && ./gradlew testDebugUnitTest` (UiScale, FavoritesStore, UsageRanking, FeedBuilder/FeedItem, FocusModel, SectionedGridFocus, AppGrouping, FavoritesRowLayout, BackdropPlanner, BackdropBlur, CenterKey, LaunchCounter, FeedInfoLine, Rating, BackdropKeys, LinkState, WeatherModel/WeatherDisplay, IdleTimeline (settings-driven), MinuteTick, LauncherSettings, GeocodingModel, RecentApps, StarfieldModel, StarSprite, OverlayDrift, ScreensaverKind, VideoPlayback, PosterSampling, TrimPolicy, VpnApps, BackdropVignette, WeatherRefreshPolicy, TitleMatch, KinopoiskInfo, KinopoiskModel, KinopoiskCache, FeedPageShift).

- Shadows: every tile/card has a `ShadowView` sibling behind it (`@id/shadow`: favorites + apps button, both feed rows, AllApps grid; not header icons) with exactly the tile's bounds. It blits one pre-rendered blurred rounded rect (`ShadowGeometry`: blur 20dp, offset 5dp down, black 42 %; ALPHA_8 bitmap, rendered once per tile size via BlurMaskFilter into a 2 MB LruCache, no per-frame blur). Chosen over elevation shadows because the platform spot light makes the offset direction depend on screen position and the softness cannot be tuned; a view-level bitmap also scales with the card (`Tiles.setSelected` applies the same scale to the shadow). Parents must have clipChildren=false. Draw order: glass (page's first child), shadow, tile.
- Long-press menus (favorites, AllApps grid) end with «Управление приложением» -> system app-info page (`AppInfoScreen`).

- Brightness (`FocusDim`, OLED): everything unfocused is dimmed, only the focused element is full. Top bar items and the weather item (`Role.TOP_BAR`) alpha 0.55; other text (AllApps names) 0.8, clock/date 0.75, tiles/cards/header icons 0.75 brightness via `DimImageView` (LightingColorFilter, not transparency); 150 ms animation. The glass highlight is the first child of the page (drawn behind tiles/cards).

## Screensaver
- `Screensaver` (FrameLayout) = background + `ScreensaverOverlay` (the ONE clock/date/weather block: white 15 %, centred, `OverlayDrift` every few minutes, own minute tick, runs only while shown). Used by `IdleController` and `StarfieldDream`; `prepare(settings)` swaps the background each time the screensaver is shown.
- Types (`LauncherSettings.screensaverType`, default STARFIELD): STARFIELD «Звёзды», NASA_VIDEO «Видео NASA». Selection rule `ScreensaverKind.choose(type, VideoPlayback.Phase)`: «Видео NASA — потоково, ничего не хранится; пока видео не началось или если сеть недоступна — звёзды». The starfield is always the base layer; the video layer (alpha 0) is crossfaded in (1.5 s) only for NASA_VIDEO in phase RENDERING (first frame, `MEDIA_INFO_VIDEO_RENDERING_START`), and back out when the phase becomes GAVE_UP.
- Stars (`StarfieldView`, model `StarfieldModel`, count = `DEFAULT_STAR_COUNT` in one constant): ~30 fps; per size class one pre-built ALPHA_8 gaussian sprite (`StarSprite`: FWHM = max(nominal size, 1.5 px); smaller stars are dimmed by the area ratio so they stay tiny without flicker). Drawn with `Canvas.drawBitmap(sprite, x, y, paint)` at float positions, Paint ANTI_ALIAS + FILTER_BITMAP (bilinear -> energy spreads over neighbouring pixels = smooth sub-pixel motion; the old drawPoints snapped dots to pixels). ALPHA_8 bitmaps are tinted by the paint colour, brightness is the paint alpha; draws are grouped per size x colour x brightness (48 buckets, counting sort in preallocated arrays, zero per-frame allocation) so the GPU batches same-texture/same-paint quads. drawVertices was not used: per-vertex colour modulating an ALPHA_8 shader is less predictable across GPU drivers and cannot be verified without the device.
- Video: playlist = `nasa_videos` in config.xml (direct https URLs, streamed in order, `nasa_credit` = «NASA SVS / STScI / ESA», shown in the settings note under «Тип заставки»). **To repoint to a mirror change only these URLs.**
- `VideoScreensaverView`: transparent layer over the starfield, nothing is downloaded or stored. Two stacked TextureViews, one MediaPlayer each (muted, `setDataSource(url)` = progressive HTTP, `prepareAsync`), centre-crop by view scale (`VideoPlayback.centerCropScale`), black overlay alpha 0.15 (max 85 % brightness). The next clip is prepared (streamed) `PREPARE_LEAD_MS` (5 s) before the crossfade, which starts `CROSSFADE_MS` (1.5 s) before the front clip ends. Pure state machine `VideoPlayback.nextPhase` (LOADING -> RENDERING; any error or `STARTUP_TIMEOUT_MS` = 15 s without a first frame -> GAVE_UP, final for this screensaver session: all players released, starfield stays). Players are released whenever the view is not attached/shown (screensaver ends). Not verified on the device: codec/profile of the NASA files and reachability of svs.gsfc.nasa.gov from Russia.
- Memory: the backdrop is static (`PosterBackdrop`; a hardware layer only while a fade runs, `withLayer`). Full-screen groups that fade use `FlatFrameLayout` (`hasOverlappingRendering=false`: `Screensaver`, `top_block`), the idle dim is a plain black View. `onTrimMemory` (MainActivity, AllAppsActivity; `TrimPolicy`: level >= UI_HIDDEN) evicts `PosterCache` memory, `BackdropController` (LRU + shown bitmap, asked for again in onStart) and the `ShadowView` cache; the screensaver start evicts the backdrop LRU. Budgets: poster LRU 8 MB (decoded with inSampleSize, then scaled to cover the card exactly, `PosterSampling`), shadow cache 2 MB, blurred backdrops ARGB_8888 (565 banded), `AppBackdropImage.MAX_SIDE` 256. Research: sandboxes/research/memory-optimization.md.

## Launcher settings screen
- `LauncherSettingsActivity` (top-bar sliders icon; `open(ctx, focusCity)`), black + glass like the home, D-pad list: «Заставка» on/off (also writes the system `screensaver_enabled` through `SystemScreensaver`; needs WRITE_SECURE_SETTINGS, granted by the install script), its delay and «Тип заставки» (Звёзды / Видео NASA; the note under it shows the NASA credit and «ничего не сохраняется» for NASA), «Кнопка VPN» (Показывать / Скрыть) and «Приложение VPN» (LEFT/RIGHT through installed VPN apps), «Притемнять интерфейс» on/off and its delay (LEFT/RIGHT cycle, OK toggles), «Масштаб интерфейса» (70-130 % in 5 % steps, LEFT/RIGHT, stops at the ends; saves, then `recreate()`s the settings activity and keeps the focused row via onSaveInstanceState), «Город» (current city + UTC label), «Определить автоматически» (`ipwho.is`; refused with «Выключи VPN…» while a VPN is up) and «Выбрать вручную» (text field + Open-Meteo geocoding, `GeocodingClient`/`GeocodingModel`, language ru). Values persist at once: `LauncherSettings` (pure) in `LauncherSettingsStore` (prefs file `launcher_settings`); the home reads them in onStart.
- The city is stored in `WeatherPrefs` under the `g2_` key prefix (lat, lon, city, country, tz; `g1_`-less older data is ignored). Its timezone drives the home clock (`TextClock.setTimeZone`), the date and the screensaver clock (`StarfieldView.setTimeZone`; minute tick via `MinuteTick`); no city = device timezone. Applied in onStart and on ACTION_TIMEZONE_CHANGED.

## Permissions
READ_TV_LISTINGS (runtime, pm grant), PACKAGE_USAGE_STATS (app-op via appops), INTERNET (posters), ACCESS_FINE_LOCATION (SSID). Re-run `tools/build-and-install.sh install` after any reinstall that clears grants.

## Behaviour
- Focus is virtual (MainActivity.dispatchKeyEvent), one glass highlight view glides to the latest target.
- Held LEFT/RIGHT (50 ms key repeat, androidtv-yxp): FocusModel advances on every repeat, a press clamped at a row end (`move()==false`) does nothing visual, visuals are applied at most once per frame (`scheduleFocusVisuals`, postOnAnimation). `SelectionDelta` (pure) tells which views change: only the previously and newly focused view get dim/scale/alpha changes; the info field fades only on a row change (text is just replaced within a row). MainActivity keeps `appliedSelection`; null (first run, `updateCounts` = data reload) means a full apply; adapters' `onBindViewHolder` set the static focus state from `setSelected`. Motion is `Approach` (exponential approach, TAU 40 ms, frame-rate independent, retargetable, no bounce/overshoot): `GlassView` (no restart, no-op for an equal target, no allocations) and `RowScroller`/`RowScrollModel` (one continuous scrollBy-driven scroll per row instead of a restarted smoothScrollBy; same tau so the glass stays on its tile). The glass target is the tile's place at the scroll TARGET (layout position - `RowScroller.pending()`); tiles not laid out yet are located from the fixed favorites geometry / feed card widths (`FeedAdapter.cardWidthPx`). `DimImageView`: one reusable ValueAnimator, shared ColorFilters cached per 1/50 brightness step. Tests: `HeldKeyScrollTest`, `SelectionDeltaTest`.
- Wi-Fi SSID needs ACCESS_FINE_LOCATION (granted by the install script); otherwise the label shows "Wi-Fi".
- Network item (`LinkState`, `NetworkStatus`): Wi-Fi glyph `ic_wifi_0..4` from `WifiManager.calculateSignalLevel(rssi)` (0-4, updated on the network callbacks), `ic_ethernet` when an ethernet network is up (wins over Wi-Fi), `ic_wifi_off` + «Нет сети» without a link.
- Gear: one glyph `ic_gear`; plain white (26dp, `TopBarItem`, FocusDim TOP_BAR) both on the home top bar and as the Settings button of the AllApps header (`settings_package` in config.xml, centred in the 44dp footprint of the store icons).
- Font: Outfit variable (OFL, see OFL.txt).
- UI scale: `LauncherSettings.uiScalePercent` (prefs key `ui_scale_percent`, default 100; a stored value not in `UiScale.PERCENTS` -> 100). Pure rules in `UiScale` (values 70..130 step 5, `fromStored`, `next`/`prev` clamped, `densityDpi(base, percent)` = round(base * percent / 100)); `UiScale.wrap(base)` (called from `attachBaseContext` of MainActivity, AllAppsActivity, LauncherSettingsActivity) = `createConfigurationContext` with `densityDpi` scaled and everything else (incl. fontScale) untouched, so all dp/sp sizes follow while the screen's pixel size stays. MainActivity remembers the scale it was created with and `recreate()`s in `onRestart` when the stored one differs (return from settings). All size code reads `getResources().getDisplayMetrics()` of an activity/view context (no application-context metrics bypass the override; `AppLoader` only keeps the application context for PackageManager). `StarfieldDream` (system screensaver service) is NOT scaled - it has no activity and runs in the dream's own context; the idle screensaver inside the launcher (`Screensaver` over the home) is scaled with MainActivity. Stale prefs key `ambient_id` from the removed ambient-video feature is ignored (no migration).
- `PlaylistVideoView`: two-slot TextureView/MediaPlayer crossfading playlist player (source resolver, muted flag, `VideoPlayback.Phase` reports); `VideoScreensaverView` is its thin wrapper for the NASA screensaver (85 % brightness dim, attach/shown lifecycle). Kept from the removed ambient-video feature, to be reused for the YouTube backgrounds later.
